# Персональный дашборд продаж Amazon

Статическая страница на GitHub Pages: **https://hoffenbachhafurov.github.io**

Данные показываются только после входа по логину и паролю. Три языка
(русский, английский, украинский), светлая и тёмная темы.

Демонстрационный набор открывается парой **`demo` / `demo-2026`** — цифры в нём
синтетические, реальных продаж там нет.

---

## 🔴 Как здесь устроена защита — прочитать до того, как класть реальные цифры

GitHub Pages отдаёт **только статические файлы**. Сервера, который проверил бы
пароль, там нет и быть не может. Поэтому обычная проверка вида «если пароль
верный — покажи данные» защитой не является: данные лежали бы рядом в открытом
виде, и любой человек увидел бы их через `Ctrl+U` или DevTools, не зная пароля.

Здесь сделано иначе. В репозитории лежит **шифротекст**:

```
ключи = PBKDF2-SHA256(логин + "\n" + пароль, salt, 600 000 итераций) → 64 байта
        первые 32 → ключ AES-256-CBC, вторые 32 → ключ HMAC-SHA256
ct    = AES-256-CBC(JSON, сжатый gzip)
tag   = HMAC-SHA256(iv || ct)          # encrypt-then-MAC
```

Логин и пароль ни с чем не сверяются — **из них выводится ключ**. Неверная пара
даёт неверный ключ, HMAC не сходится, расшифровка даже не начинается. Ни пароль,
ни его хеш нигде не хранятся: восстановить их из репозитория нечем.

**Что из этого следует практически:**

| Факт | Следствие |
|---|---|
| Репозиторий публичный, шифротекст доступен всем | Пароль можно подбирать офлайн, без ограничения попыток |
| Единственная преграда — стойкость пароля | Короткий или словарный пароль подберут. Нужна **длинная случайная фраза**, не «Amazon2026» |
| 600 000 итераций PBKDF2 | Каждая попытка перебора стоит примерно секунду процессорного времени. Это замедляет перебор, но не отменяет его |
| Расшифрованные данные живут только в памяти вкладки | Обновление страницы требует повторного входа. Так задумано: иначе выручка осела бы на диске |
| Адрес сайта публичен | Приватность репозитория адрес не закрывает. Закрытый доступ к Pages есть только в GitHub Enterprise |

> Если однажды понадобится настоящая серверная авторизация — статический хостинг
> придётся менять. В рамках GitHub Pages описанная схема это максимум,
> и она честная: без пароля данные нечитаемы.

## Как обновить данные

Файл с данными — `data/dashboard.enc.js`. Собрать его можно двумя способами.

### Способ 1. PowerShell (основной)

Совпадает со стеком остального проекта: выгрузку из SP-API можно передать
сразу в этот скрипт.

**Шаг 1 — получить стойкий пароль.** Он печатается только в вашей консоли:

```powershell
cd tools
.\New-Passphrase.ps1
```

**Шаг 2 — зашифровать данные:**

```powershell
.\New-DashboardData.ps1 -InputPath ..\sales.json -User ваш_логин
```

Скрипт спросит пароль дважды (через `Read-Host -AsSecureString`, поэтому в
историю команд он не попадёт), зашифрует данные и запишет
`data/dashboard.enc.js`. Дальше — обычный `git commit` и `git push`.

Пересобрать демо-набор — под публичной парой либо под своей:

```powershell
.\New-DashboardData.ps1 -Demo                  # demo / demo-2026
.\New-DashboardData.ps1 -Demo -User ваш_логин  # спросит собственный пароль
```

Второй вариант удобен, чтобы проверить вход до появления реальных цифр.

### 🔴 Три правила про пароль

1. **Не передавать параметром командной строки** — осядет в истории PSReadLine
   открытым текстом.
2. **Не пересылать в переписке, чате или почте.** Пароль, попавший в сообщение,
   считается скомпрометированным — его нужно менять и пересобирать файл данных.
3. **Не брать словарный.** `qwerty11`, `amazon2026` и подобные подбираются за
   секунды: шифротекст публичен, перебор идёт офлайн без ограничения попыток.
   Нужна длинная случайная строка — её выдаёт `New-Passphrase.ps1`.

Пароль нигде не хранится. Потеряете — файл данных придётся собрать заново
(сами данные при этом никуда не денутся, они есть в исходной выгрузке).

### Способ 2. Браузер

Открыть `tools/encrypt.html` с диска (двойным щелчком, сайт для этого не нужен).
Вставить JSON, задать логин и пароль, нажать «Зашифровать» и скачать готовый файл.
Всё считается локально, никуда ничего не отправляется. Там же есть кнопка
проверки — расшифровать только что собранный файл, не выходя со страницы.

## Контракт данных

JSON, который подаётся на шифрование:

```json
{
  "meta": {
    "generatedAt": "2026-08-04T21:00:00Z",
    "storefront": "GermanyProducts24",
    "defaultCurrency": "EUR"
  },
  "marketplaces": [
    { "id": "DE", "name": "Amazon.de", "currency": "EUR" }
  ],
  "days": [
    { "date": "2026-08-04", "marketplace": "DE", "currency": "EUR",
      "revenue": 1234.50, "units": 42, "orders": 33 }
  ],
  "skus": [
    { "date": "2026-08-04", "sku": "GP-KTL-1700", "name": "Электрочайник 1.7 л",
      "marketplace": "DE", "currency": "EUR", "units": 12, "revenue": 418.80 }
  ]
}
```

| Поле | Обязательное | Замечания |
|---|---|---|
| `meta.generatedAt` | нет | Показывается в шапке как «Обновлено» |
| `meta.defaultCurrency` | нет | Какая валюта выбрана при открытии |
| `marketplaces[].id` | да | Должен совпадать с `days[].marketplace` |
| `days[].date` | да | Строго `ГГГГ-ММ-ДД` |
| `days[].currency` | да | Валюты **не суммируются между собой** — см. ниже |
| `skus[].date` | да | По нему работает фильтр периода |

**Валюты не сводятся на одну шкалу.** EUR, GBP, SEK и PLN — разные единицы,
складывать их в одну сумму нельзя. Поэтому валюта вынесена в фильтр: показатели
и графики выручки всегда считаются по одной валюте. Это прямое следствие того,
что реальный аккаунт торгует в 18 маркетплейсах на четырёх валютах.

Периоды («7 дней», «30 дней», …) отсчитываются от **последней даты в данных**,
а не от сегодняшнего числа: выгрузка бывает вчерашней, и отсчёт от «сегодня»
давал бы пустой экран.

## Устройство

```
index.html                     вход + дашборд, одна страница
assets/css/tokens.css          палитра и типографика (светлая/тёмная)
assets/css/app.css             раскладка и компоненты
assets/js/vault.js             шифрование: PBKDF2 + AES-CBC + HMAC
assets/js/i18n.js              три языка
assets/js/format.js            числа, деньги и даты через Intl
assets/js/charts.js            графики на чистом SVG
assets/js/app.js               фильтры, темы, отрисовка карточек
data/dashboard.enc.js          зашифрованные данные
tools/New-DashboardData.ps1    сборка файла данных из PowerShell
tools/New-Passphrase.ps1       генератор стойкого пароля
tools/encrypt.html             то же самое в браузере
tools/demo-data.js             генератор демонстрационного набора
```

**Ни сборки, ни зависимостей.** Ни npm, ни бандлера, ни внешних библиотек —
графики нарисованы вручную на SVG. Причина простая: на машине разработки нет
Node.js, а GitHub Pages отдаёт статику как есть. Скрипты подключаются обычными
`<script>`, а не ES-модулями, поэтому страница одинаково работает и с сайта,
и открытая с диска.

### Правила отрисовки графиков

Визуальный слой следует методичке dataviz, а не вкусу:

- палитра взята эталонной и **не менялась** — её порядок слотов является
  механизмом различимости при дальтонизме, а не украшением;
- **никаких двух шкал Y** на одном графике;
- одна серия — один цвет; закраска «чем больше, тем темнее» на номинальных
  категориях запрещена (она дважды кодирует одну и ту же длину);
- сетка и оси — волосяные и сплошные, никогда не пунктир;
- столбцы не толще 24px, скругление 4px только на конце-значении;
- подписи выборочные: число над каждой точкой не ставится;
- цвет серии носят марки, а не текст;
- у каждого графика есть **табличный двойник** (кнопка «Таблица») — значение,
  доступное только по наведению, недоступно с клавиатуры и скринридера;
- больше восьми категорий цветом не кодируются: хвост сворачивается в «Прочее».

### Доступность

Переключение графика в таблицу, работа с клавиатуры (стрелки водят перекрестие
по линейным графикам), видимый фокус, `prefers-reduced-motion`, ссылка «перейти
к содержимому», подписи `aria-label` на графиках, направление дельты
подкреплено стрелкой, а не только цветом.

## Локальный просмотр

Достаточно открыть `index.html` двойным щелчком — данные подгружаются обычным
скриптом, а не `fetch`, поэтому запрет CORS для `file://` не мешает.

Проверка вёрстки без ручного открытия браузера (Node.js на машине нет):

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --headless --disable-gpu --hide-scrollbars --window-size=1440,1500 `
  --screenshot="out.png" "file:///C:/путь/к/index.html"
```

⚠️ Виртуальное время Edge (`--virtual-time-budget`) проматывается мгновенно и
**не ждёт Web Crypto** — снимок поймает экран входа в момент расшифровки.
Для проверки самого дашборда собирайте временный файл данных с малым числом
итераций: `-Iterations 1000`.
